# 拼豆小纸条 V0 产品方案

## 1. 项目背景

我们正在做一个免费、自用/朋友可用的拼豆图纸生成 H5 小工具。

项目基于现有拼豆图纸生成能力进行改造，但最终希望呈现为一个独立、可爱、移动端友好的前台工具，而不是专业工作台、后台管理系统，或原开源项目的镜像页面。

当前核心目标是：

> 用户在手机上上传一张图片，选择用途和生成效果，系统生成一张可以照着拼的拼豆图纸，以及一张豆子用量图。

## 2. 产品定位

产品名称暂定：

> 拼豆小纸条

一句话定位：

> 把你的图片变成一张可以照着拼的拼豆小纸条。

产品说明：

> 上传一张喜欢的图片，生成拼豆图纸和豆子用量图，适合做挂件、冰箱贴和摆件。

## 3. 产品形态

### 3.1 页面形态

采用移动端优先的 H5 页面。

优先适配手机浏览器，尤其是 390×844 视口。

不是：

* 小程序
* 桌面专业工作台
* 内部运营后台
* 商业化平台
* 图纸社区

### 3.2 页面入口建议

如果当前项目已有内部工作台页面，请保留它，不要直接改成用户端页面。

建议新增用户端页面：

```text
/generate
```

或者：

```text
/
```

如果 `/` 已经是内部页，则先用 `/generate`。后续准备对朋友开放时，再考虑将 `/` 指向用户端 H5。

### 3.3 内部页面与用户页面关系

当前已有的内部页面如果包含：

* 案例列表
* 新增提交
* 来源渠道
* 内部状态
* 品牌调试字段
* 运营记录字段

这些都应保留在内部后台，不应出现在普通用户 H5 页面里。

用户端 H5 只保留：

```text
上传图片 → 选择用途 → 选择效果 → 生成图纸 → 保存结果
```

## 4. 目标用户

V0 面向：

1. 自己和朋友。
2. 拼豆新手。
3. 想把宠物、头像、角色、可爱图案转成拼豆图纸的人。
4. 手机端使用为主的用户。

暂不面向：

1. 专业拼豆设计师。
2. 批量商家。
3. 图纸售卖用户。
4. 社区创作者。
5. 需要复杂编辑器的重度用户。

## 5. 产品目标

V0 的目标是跑通一个轻量、可爱的手机端生成体验：

```text
上传图片
↓
选择用途
↓
选择图纸效果
↓
生成
↓
得到两张图片
↓
长按保存到相册
```

V0 成功标准：

1. 用户不用理解复杂参数，也能完成图纸生成。
2. 用户最终能拿到两张 PNG：

   * 拼豆网格图纸
   * 豆子用量图
3. 页面在手机端看起来像一个可爱的小工具，而不是后台系统。
4. 5 张以上测试图片能完整跑通流程。

## 6. 非目标范围

V0 不做：

1. 用户登录。
2. 支付。
3. 会员。
4. 图纸社区。
5. 作品展示墙。
6. 图纸库。
7. AI 生图。
8. 小程序。
9. 分享卡。
10. Excel/CSV 作为主交付物。
11. 复杂在线编辑器。
12. 批量处理。
13. 后台运营数据大盘。
14. 商业化功能。

CSV 可以作为高级能力或内部备份能力保留，但不要进入普通用户主路径。

## 7. 核心用户流程

完整流程：

```text
进入页面
↓
看到可爱的产品说明
↓
点击开始生成 / 上传图片
↓
选择图片
↓
看到图片预览
↓
选择用途：挂件 / 冰箱贴 / 摆件
↓
选择生成模式：新手友好 / 标准清晰 / 细节还原
↓
点击生成拼豆图纸
↓
等待生成
↓
看到两张结果图：
1. 拼豆网格图纸
2. 豆子用量图
↓
长按保存到相册
```

## 14. 背后参数映射建议

具体技术参数由 Codex 根据现有代码实现决定，但产品层建议如下：

### 14.1 挂件

倾向：

* 小尺寸
* 色彩更少
* 难度更低
* 适合新手

### 14.2 冰箱贴

倾向：

* 中等尺寸
* 清晰度和难度平衡
* 适合默认场景

### 14.3 摆件

倾向：

* 更大尺寸
* 颜色更多
* 细节更多
* 难度更高

### 14.4 新手友好

倾向：

* 降低颜色数
* 降低碎色块
* 保留主体轮廓
* 优先可拼性

### 14.5 标准清晰

倾向：

* 平衡颜色数量与还原度
* 适合作为默认模式

### 14.6 细节还原

倾向：

* 增加颜色数量
* 保留更多细节
* 图纸更复杂

## 18. 主交付物 1：拼豆网格图纸 PNG

### 18.1 用途

用户照着这张图一格一格拼。

### 18.2 卡片文案

标题：

```text
你的拼豆图纸
```

说明：

```text
可以照着这张图一格一格拼。
```

保存提示：

```text
长按图片保存到相册
```

按钮：

```text
保存图纸图片
```

按钮可以保留，但主引导是长按保存。

### 18.3 图纸 PNG 要求

拼豆网格图纸 PNG 应包含：

1. 拼豆网格。
2. 每格颜色。
3. 色号标注。
4. 坐标或分区线。
5. 图纸尺寸。
6. 品牌信息，如有。
7. 总豆数或颜色数摘要，如版面允许。

要求：

1. 手机端可预览。
2. 可长按保存。
3. 不依赖 Excel/CSV。
4. 大图可以缩放查看。
5. 不跳转到外部工具页面。

## 19. 主交付物 2：豆子用量图 PNG

### 19.1 用途

用户买豆、备料、核对颜色和数量。

### 19.2 卡片文案

标题：

```text
需要准备的豆子
```

说明：

```text

```

保存提示：

```text

```

按钮：

```text
保存豆子用量图
```

### 19.3 豆子用量图 PNG 要求

豆子用量图应包含：

1. 标题：豆子用量清单。
2. 品牌名称，如有。
3. 图纸尺寸。
4. 总豆数。
5. 颜色数。
6. 每种颜色的色块。
7. 每种颜色的色号。
8. 每种颜色需要的数量。

示例结构：

```text
豆子用量清单

颜色数：12 色

A01 黑色：68 颗
B12 奶白：120 颗

```

要求：

1. 是单独 PNG。
2. 适合手机查看。
3. 适合长按保存。
4. 不依赖 Excel。
5. 不把 CSV 作为主路径。

## 20. 保存与下载体验

### 20.1 手机端主操作

主操作是：

```text
长按图片保存到相册
```

每张图下方都需要提示。


## 26. 移动端适配要求

必须满足：

1. 390×844 视口下无横向滚动。
2. 页面主要内容单列。
3. 主要按钮高度不低于 44px，建议 48px。
4. 上传按钮、生成按钮、保存按钮适合手指点击。
5. 文案字号不要过小。
6. 结果图片在手机端可完整查看。
7. 大图可以点击查看或缩放查看，如技术上可实现。
8. 表单控件不要太密集。
9. 底部页脚不要抢占主流程。

## 27. 开源说明展示策略

首页主视觉不突出开源来源，不做大段说明。

但如果基于开源项目代码改造，需要保留开源说明和源码入口。

推荐方式：

1. 页脚放轻量入口：

```text
开源说明 · GitHub
```

2. 新增或保留 About / Open Source 页面。
3. README 中写清楚：

   * 基于哪个开源项目改造。
   * 遵循什么协议。
   * 当前工具免费自用/朋友试用。
   * 源码公开地址。

页面上不要把开源说明做得很抢眼，但不能完全删除。

## 33. 验收标准

### 33.1 页面验收

1. 手机视口 390×844 下无横向滚动。
2. 首屏能明确看懂这是拼豆图纸生成工具。
3. 页面风格可爱、清爽、手作感，不像后台。
4. 用户主路径不出现内部运营字段。
5. 用户主路径不出现过多专业参数。
6. 按钮和表单适合手机点击。

### 33.2 流程验收

1. 用户可以上传图片。
2. 上传后能看到图片预览。
3. 用户可以选择用途。
4. 用户可以选择生成模式。
5. 用户可以点击生成。
6. 生成中有状态提示。
7. 成功后展示两张结果图。
8. 失败后有友好提示。

### 33.3 输出物验收

拼豆网格图纸 PNG：

1. 能照着拼。
2. 有网格。
3. 有色号。
4. 有坐标或分区线。
5. 手机端可查看。
6. 可长按保存。

豆子用量图 PNG：

1. 有色块。
2. 有色号。
3. 有数量。
4. 有总豆数。
5. 有颜色数。
6. 手机端可查看。
7. 可长按保存。

### 33.4 样例验收

至少跑通 5 张样例图。

建议样例包含：

1. 宠物图 2 张。
2. 头像/人物图 1 张。
3. 角色/卡通图 1 张。
4. 简单图案/应援图 1 张。

记录每张图的问题：

1. 生成是否成功。
2. 是否像原图。
3. 色号图是否可读。
4. 图纸是否适合手机查看。
5. 是否有明显 UI 或保存问题。

```text
你的拼豆图纸
```
