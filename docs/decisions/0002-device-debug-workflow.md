# 0002：为真机 Bug 建立专项 Debug 技能

- 状态：已接受
- 日期：2026-07-03
- 参与者：用户、Codex
- 影响范围：阶段 F 真机验收、移动浏览器兼容、Bug 修复与复测

## 背景

真机问题通常依赖设备、系统、浏览器或微信版本，自动化测试无法替代真实保存、长按、EXIF 和手势验证。普通开发在测试通过后可以完成，但真机 Bug 必须回到原设备和原路径复测。

## 决定

保留 `pindou-develop` 作为主工作法，额外建立 `pindou-device-debug` 专项技能。它不是另一套项目管理系统，所有任务和结论仍回写同一份状态与计划。

真机 Bug 使用 `BUG-F-###` 编号，并按以下流程工作：

```text
发现 → 证据归一化 → 定级 → 修复 → 自动化回归 → 独立审查
→ 部署新候选 → 原设备复测 → 关闭或重新打开
```

## 执行规则

1. 最少记录设备、系统、浏览器/微信版本、部署 URL、commit、复现步骤、实际结果和预期结果。
2. 用户可以自然语言描述，Agent 负责整理成规范记录。
3. 一条 Bug 使用一个 `fix/BUG-*` 分支；多次尝试追加记录，不另造重复 Bug。
4. 代码通过测试和审查后，状态只能进入“待真机复测”。
5. 只有用户在原设备或约定等价设备上确认通过，才能关闭。
6. P0/P1 修复由不同 Agent 做独立审查。

## 分工

- 用户：提供真机现象与最终复测结论。
- 默认 Qoder：实现修复和补自动化测试。
- 默认 Codex：归因、定义验收条件、Code Review 和独立验证。
- 若 Codex 实现，则由 Qoder 审查。

## 重新讨论条件

- 引入设备云或稳定的自动化真机测试平台。
- 移动端迁移到原生 App，兼容矩阵发生根本变化。
