## 一、产品结构

竖屏版不是单纯的“上传并生成”页面，而是四套能力叠在一起：

1. 图片转拼豆图纸。
2. 专业图纸编辑器。
3. 实际制作过程中的进度助手。
4. PWA、打卡图、捐赠和品牌传播能力。

因此首页未上传时看起来简单，上传后会快速暴露大量专业参数和编辑入口。

## 二、完整功能清单

### 1. 上传与数据恢复

- 支持 JPG、PNG、GIF。
- 支持拖放或点击系统文件选择器。
- 支持导入该工具自己导出的 CSV 网格数据。
- CSV 导入后会恢复网格、颜色统计和合成预览图。
- 图片和图纸计算主要在浏览器 Canvas 中完成，没有业务后端上传接口。

### 2. 自动图纸生成

- 横轴格数 10–300，纵轴按原图比例计算。
- 两种像素化模式：主色模式、平均色模式。
- 使用 Oklab 颜色距离寻找最接近的豆色。
- 颜色相似度阈值 0–100，用于合并相似颜色。
- 五种色号体系：MARD、COCO、漫漫、盼盼、咪小窝。
- 291 个基础颜色映射。
- 参数变化后自动重新计算预览和颜色统计。

### 3. 色板与杂色处理

- 自定义启用/禁用颜色。
- 按色号搜索和分组浏览颜色。
- 全选、全不选、按系列全选。
- 自定义色板保存到 localStorage。
- 自定义色板配置 JSON 导入/导出。
- 点击用量列表可排除某种颜色，并自动重映射为最近颜色。
- 查看和恢复已排除颜色。
- 显示每个色号的数量和总豆数。
- 点击颜色可在图中临时高亮。

### 4. 背景与手动编辑

- 一键去背景：从边缘识别背景并做洪水填充。
- 一键去背景可撤回一步。
- 单格上色。
- 单格橡皮擦。
- 连通色块整体擦除。
- 将图中某种颜色全局替换成另一种颜色。
- 最多约 50 步手动编辑撤回。
- 浮动色板可拖动。
- 放大镜可选择区域并精细编辑。
- 手机触摸点击、拖动、滑动判断。

### 5. 图纸导出

- PNG 图纸。
- 基础格线与每 N 格分区线。
- 六种分区线颜色。
- 四边坐标。
- 格内色号可显示或隐藏。
- 图纸底部可包含色号、色块、每色数量和总豆数。
- 可同时导出 CSV 源数据。
- 图纸内置七卡瓦标题、水印、小红书标识和网站二维码。

### 6. 专心拼豆模式

- 进入前提醒下载 CSV 备份。
- 按颜色显示当前任务和完成数量。
- 点击格子标记完成。
- 画布平移、双指缩放。
- 定位推荐区域。
- 三种制作顺序：最近优先、大块优先、边缘优先。
- 分区线开关、间隔和颜色。
- 制作计时、暂停和继续。
- 单色完成和全图完成进度。
- 完成庆祝动画。
- 调用相机拍摄成品，或使用图纸缩略图。
- 生成 720×960 完成打卡 JPG。

### 7. 系统能力

- PWA manifest、Service Worker、离线缓存和安装按钮。
- 竖屏优先的 PWA 配置。
- Vercel Analytics 和访问量统计。
- 打赏二维码弹窗。
- 首次进入时展示专业工作台推荐弹窗；源码实际设置为每次页面挂载都弹。

## 三、为什么手机端仍显复杂

### 结构问题

- 上传后同时出现尺寸、合并阈值、去背景、撤回、处理模式、色号系统和色板管理。
- 自动生成、手动编辑、专心制作是三套不同任务，却在同一条页面链路中竞争注意力。
- 颜色统计列表同时承担统计、排色、恢复和高亮四种作用。
- “下载”不是直接下载，还会进入包含六组设置的弹窗。
- “专心拼豆”又带一套颜色面板、设置抽屉、计时器和完成卡。

### 文案问题

- “横轴切割数量”“颜色合并阈值”“主色/平均色”等面向专业操作者。
- 首屏仍使用“拖放”作为主要提示，不符合手机用户的相册选择心智。
- 进入专心模式前强调 CSV 备份，把数据管理责任交给普通用户。

### 视觉问题

- 品牌头图区约占 400px 高度，390×844 设备上上传入口接近首屏下半部。
- 装饰、动画、外链、来源说明、专业工作台推荐都先于用户任务。
- 多个悬浮面板和图标工具在小屏上容易遮挡图纸。

### 技术与完成度风险

- `page.tsx` 单文件约 2,825 行，页面状态高度耦合。
- 10–300 格计算在主线程 Canvas 中完成，未使用 Web Worker，大图可能卡顿。
- 页面禁止用户缩放（`userScalable: false`），存在无障碍风险。
- 主编辑状态没有完整项目持久化；进入专心模式依赖 localStorage 和 CSV 备份。
- 专心模式设置中的“导出进度数据”“重置所有进度”按钮没有事件处理，目前只是界面。
- PWA manifest 引用了仓库中不存在的 `screenshot-mobile.png` 和 `screenshot-desktop.png`。
- 非官方域名会被强制重定向到官方域名；若用于我们自己的预览或部署必须移除。
- README 对颜色距离和 `paletteOptions` 的描述与当前代码已有偏差。

## 四、对我们最有价值的参考

### 建议直接研究或抽取

- `utils/pixelation.ts`：网格计算与颜色匹配。
- `utils/imageDownloader.ts`：PNG、坐标、色号、统计和 CSV 导出。
- `utils/pixelEditingUtils.ts`：单格编辑、色块擦除和统计重算。
- `utils/colorSystemUtils.ts` 与 `colorSystemMapping.json`：品牌色号映射。
- `PixelatedPreviewCanvas.tsx`：Canvas 绘制和手机触摸判断。
- `DownloadSettingsModal.tsx`：了解全部导出参数，但不建议原样照搬 UI。

### 建议改成高级功能

- 阈值、模式和自定义色板。
- 色号排除与全局替换。
- 单格编辑和放大镜。
- CSV 导入导出。

### 第一版不建议照搬

- 专心拼豆完整模式。
- 完成庆祝、相机打卡图。
- 可拖动的浮动面板。
- PWA 安装引导。
- 打赏和外链区域。
- 每次进入都出现的专业工作台弹窗。

## 五、建议我们的移动端结构

默认只保留四步：

1. 选择图片。
2. 选择用途 preset。
3. 查看一张主预览，可选“一键去背景”。
4. 保存图纸与豆子用量图。

将“尺寸、色板、杂色、手动编辑、CSV”统一收进高级设置。这样可以复用它的大部分底层算法，同时避免复制其产品复杂度。

## 六、界面核查记录

### 步骤 1：首次进入

- 截图：`01-entry.png`
- 健康度：可用，但阻断任务。
- 发现：每次挂载都会弹出专业工作台推荐，用户尚未上传就需要做产品选择。

### 步骤 2：上传入口

- 截图：`02-upload.png`
- 健康度：入口清晰，但品牌头部偏重。
- 发现：页面没有横向溢出，上传区域触控面积充足；上传入口被约 400px 的品牌区域推到页面中段。

### 步骤 3：上传后生成与编辑

- 健康度：能力丰富，信息过载。
- 证据限制：本轮没有向第三方线上站点上传测试文件；该步骤依据当前克隆源码逐项核查，未对真实手机的图片选择器、下载行为和性能作完整端到端验证。
